# Widget Lab

A private, native Android collection of 19 home-screen widgets. Kotlin, Compose and real `AppWidgetProvider` / `RemoteViews` providers; no server, account, ads or analytics. Android 10–15 (min 29, target 35).

The application includes a collection gallery, previews generated by the widget renderer, detail/configuration screens, launcher pinning, installed-instance editing, recent styles, source timestamps, manual refresh and permission diagnostics. Profiles are independent for each launcher widget ID and survive process death and device restart.

## Build and install

Requires JDK 17 or 21 and Android SDK platform 35/build tools 35.0.0. Set `ANDROID_HOME` or put `sdk.dir=/your/android-sdk` in the ignored `local.properties`.

```sh
./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

Or open this directory in Android Studio. A computer is needed to build, not to use the installed application. The development APK is signed with an Android development key. Allow APK installation from your chosen file browser, install, then open Widget Lab. Pick a design and use **Add to Home Screen**, or long-press the launcher → Widgets → Widget Lab. Some launchers require manual placement.

## GitHub Actions / private distribution

Push this directory to a **private GitHub repository**. The included Android APK workflow builds on `main`, pull requests, or manual dispatch. Download **Widget-Lab-development-APK** from a successful run’s Artifacts area and extract the APK on your phone. A cache retains the development keystore on a best-effort basis. If the cache is lost, that APK cannot update an installation signed by the previous key; uninstalling also removes local profiles. Use a private release key for durable updates.

To produce a stable, signed private release, generate and securely back up your own key, then configure repository Actions secrets:

- `WIDGETLAB_KEYSTORE_BASE64`: base64-encoded JKS/PKCS12 keystore.
- `WIDGETLAB_STORE_PASSWORD`
- `WIDGETLAB_KEY_ALIAS`
- `WIDGETLAB_KEY_PASSWORD`

The workflow prepares the key in the runner’s temporary directory, signs the release, uploads **Widget-Lab-private-release-APK**, and deletes the temporary key. Keys and passwords never belong in git. Increment `versionCode` for subsequent releases. Without signing secrets, release compilation is checked but only the installable development APK is distributed. Never install an unsigned release APK. GitHub hosting and workflow execution require your repository; no repository was connected automatically.

A separate **Android 15 device checks** workflow can be run manually on GitHub’s hardware-accelerated emulator runner. It exercises real widget binding/layout inflation and controlled media-session routing/revocation. It does not replace physical Vivo or third-party-player acceptance.

### Racing

Public HTTPS endpoints verified during development:

- `https://api.jolpi.ca/ergast/f1/current/driverstandings/?limit=100`
- `https://api.jolpi.ca/ergast/f1/current/constructorstandings/?limit=100`
- `https://api.jolpi.ca/ergast/f1/current/?limit=100`
- `https://api.jolpi.ca/ergast/f1/current/last/results/?limit=100`

Each feed has its own atomic app-private cache, successful-refresh timestamp and error status. Automatic sync runs approximately every six hours with a network constraint. A manual pass makes four requests and has a one-minute cooldown. Failures preserve the previous successful feed. More than 24 hours old is labeled **CACHED**; failures show **OFFLINE**. Data is a snapshot, not live timing. Standings show season and round. Multiple constructors on a driver record represent that season’s teams; constructor abbreviations are season participants, not a fabricated current lineup.

Before the first successful feed, the app displays **SAMPLE / 2024 · OFFLINE STUDY**. These historical examples describe Monaco 2024 and are never presented as current. Missing session times remain TBA. Session instants are converted with `java.time.ZoneId` and daylight-saving rules. Sprint sessions are parsed individually. Unknown circuit IDs use circuit names, never a misleading generic outline. An original simplified Monaco outline is included. No advanced telemetry is implemented.

A cropped, attributed **2021 archival Hamilton portrait** is bundled. It is separate from the season-specific standings; no current affiliation is inferred from the photograph. Other driver portraits and personal car art can be imported through Android’s document picker. Images are orientation-corrected, bounded to 1024 pixels and stored privately. Missing art uses deliberate typography/geometric identifiers. Team wordmarks are text; no unlicensed team logos/car photographs are bundled.

### Music

Enable media access from a music design. Android’s notification-listener grant permits querying active media sessions; Widget Lab does not read notification message bodies or persist metadata. A connected `NotificationListenerService`, active-session listener and `MediaController.Callback` respond to metadata/playback changes. Automatic selection prefers a playing session; an instance can prefer a specific currently available player. If that session disappears, automatic selection resumes.

Previous, play/pause and next use the chosen session’s transport controls and published action flags. Unsupported buttons are dim and open configuration. Tapping artwork/body opens the session’s activity or associated media app when available. No progress is fabricated. Vinyl and cassette drawings are static. “Soft glass” is a layered illustration, not live wallpaper blur. No music is streamed by Widget Lab. Compatibility depends on the player exposing a media session.

### Essentials and Android scheduling

Clock/date providers contain native **TextClock** views with selected IANA zones. They do not depend on background jobs for minute accuracy. Gallery clock/date previews use the same design data with a Canvas text approximation; native font layout can vary with launcher/device font scale.

Battery reads real `ACTION_BATTERY_CHANGED` data. A foreground app-process receiver, power broadcasts, widget updates and a 30-minute WorkManager pass refresh battery/agenda/countdown data. There is no permanent polling service. Android, Doze and Vivo power settings may delay these approximate intervals. Countdown shows days/hours and intentionally has no seconds.

Agenda requests only `READ_CALENDAR`, from its own detail screen. It queries visible local calendars for upcoming seven-day instances, including recurring events. Permission-denied, no-events and provider-failure states are explicit. All-day events use their calendar UTC date; timed events use the configured zone. Calendar titles are drawn only locally, not uploaded. Tapping the agenda opens its configuration.
